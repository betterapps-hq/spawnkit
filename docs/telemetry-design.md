# SpawnKit telemetry

Design and implementation contract, 2026-10-14.

This document describes the current bounded logger. The proposed [analytics architecture and regional routing](telemetry-analytics-architecture.md) extends it with ClickHouse/ClickStack, game analytics and the agreed requirement for EU endpoints selected from server location. Those extensions are not yet implemented.

## Scope and decisions

Build an installable, dependency-free browser/Node telemetry logger in `@spawn/telemetry`. Support named events, leveled logs, exceptions with bounded breadcrumbs, numeric measurements, release/environment/session context, explicit trace/span correlation, consent, and a `beforeSend` hook. Use OTLP/HTTP JSON logs as the wire contract (resourceLogs/scopeLogs/logRecords, nanosecond decimal strings, standard severity numbers, hex trace IDs). Provide an adapter for the official OpenTelemetry log SDK. Measurements are log events, not an OTLP metrics implementation; manual trace context is accepted, but no global tracing provider is installed. Session replay, DOM/network autocapture, user profiling, source-map symbolication, alert delivery, full APM traces/metrics, and feature flags are outside this logger release.

Tenant means a SpawnKit project in the platform-owned Cloudflare account, consistent with the existing platform specification. Use a dedicated telemetry Worker and one SQLite Durable Object per project/environment. Do not put telemetry in the control database or shared artifact bucket. Durable storage acknowledges accepted batches synchronously; a successful HTTP response means persistence, while timeout retries deduplicate by event ID. Per-tenant objects distribute ingestion/query load horizontally. Bounded per-tenant volume is a deliberate first-release service tier, not an unlimited analytics promise.

## SDK contract

`createTelemetry({ endpoint, key, serviceName, release, environment, consent, sampleRate, errorSampleRate, beforeSend, ...transportLimits })` returns an independent instance. `track(name, attributes)`, `log(level, message, attributes)`, `captureException(error, attributes)`, `measure(name, value, unit, attributes)`, `addBreadcrumb(...)`, `setContext(...)`, `setConsent(...)`, `resetSession()`, `flush()`, and `shutdown()` compose without a global singleton. Trace context can be supplied explicitly or forwarded by the OpenTelemetry adapter. Generated game adapters expose the existing initializeTelemetry/track/captureError functions.

- Capture is disabled until consent is granted. Revocation clears queued records, context and breadcrumbs, resets session identity, and aborts active requests; already accepted records require server retention/deletion. No cookies, local storage, device fingerprint, email, player identity, URL, IP, or user agent collection. Browser error handlers are opt-in and removable; no console/fetch monkey-patching.
- Sanitize at capture time and again after beforeSend. Bound attribute count, key and string length, stack size, depth, breadcrumbs, event size, queue count and bytes. Redact common secret/PII keys and obvious token/URL query/email patterns in free text. Reject unsupported/prototype/getter data safely. Redaction is best effort; applications must avoid placing personal data in event names/messages/attributes. Hook failures drop that record and never escape into gameplay.
- Default limits: 200 queued records, 256 KiB queue, 20 records and 48 KiB per batch, 8 KiB per record, 20 breadcrumbs, 5-second interval/request timeout. Oversize records are dropped. Drop oldest when full, prioritize errors where practical. Expose counters for queued/sent/dropped/retries; never recursively log transport errors. Validate options on creation; capture/transport errors are isolated.
- Retain event IDs across retries. One in-flight flush, exponential jitter, bounded retries and queue age (independent of source timestamps), Retry-After, retry only network/timeouts/429/502/503/504. HTTP 408 is terminal under OTLP. Terminal errors drop affected records. OTLP partial success drops rejected records without retrying the batch. Flush resolves a status rather than throwing and has a bounded work budget. Shutdown removes listeners/timers, flushes within its budget, and reports unsent records. Visibility/pagehide uses small fetch keepalive batches, with documented best-effort delivery. No persistent offline queue.

## Ingestion, isolation and storage

- The public Worker supports POST `/v1/logs` with a project/environment write key and origin allowlist. Keys are signed tokens containing project, environment and a random generation. Verify signature and shape before allocating/accessing a tenant object; check current generation in the object for revocation. A browser key is public configuration, never a read/admin credential. No wildcard origins, credentials, query-string keys, or redirects. Missing Origin is allowed for server clients; Origin is an abuse signal, not authentication.
- A separate service-binding-only admin entrypoint is called by the control API after its existing Clerk authentication and project ownership checks. It configures/rotates/disables ingestion, queries records, and deletes tenant telemetry. Public routes cannot invoke admin operations. Admin requests choose tenant from authenticated route scope, never payload scope.
- Mandatory edge IP/key rate limits, plus atomic object quotas (10,000 accepted records/day/environment and bounded request rate). Maximum request body 48 KiB, batch 20 and record 8 KiB; enforce streamed read limits and content type, validate OTLP supported shapes/counts, reject an entire invalid batch with a clear 4xx. Canonical server tenant/environment overrides untrusted resource attributes. No cross-tenant joins or unscoped queries.
- Store event ID, received time, event time, severity/kind/name, release/session/trace/span, sanitized attributes, body/stack/breadcrumbs. Unique event ID deduplicates retries. Separate received time controls retention and ordering; reject unreasonable client timestamps. Keyset pagination by received time and event ID, explicit bounds and indexes. Max page 100, bounded search/time range. Error grouping uses sanitized type/message/stack fingerprint, not a user-supplied identity.
- Seven-day retention with scheduled object alarms, bounded cleanup batches and a hard row ceiling. Queries hide expired records even before physical cleanup. Keep config separate from deletable records. Expose limit and retention metadata; monitor rejection/latency/storage through Worker observability without logging bodies or keys. At quota return 429 and retry delay; at temporary storage failure return 503, never false success.

## Dashboard and scaffolding

Authenticated project telemetry routes proxy to the service binding. A live telemetry panel in project Logs fetches with project/environment/filter-scoped query keys, bounded polling, cancellation, explicit empty/loading/error/offline states, pagination, severity/kind/release filters, event details, trace context and grouped errors. Keep Storybook fixture behavior separate through an explicit live mode. Setup UI creates/rotates the write key for allowed game origins and exposes copyable environment configuration; show public-key status accurately. Stored logs and keys never enter unrelated project caches.

CLI `--add platform-telemetry` uses the shared template contract. The package is initially delivered as a vendored local package in standalone scaffolds because the telemetry SDK is distributed inside each generated project; generated files must not use workspace paths or require unpublished registry dependencies. Also produce a normal npm-installable package tarball. Default generated environment configuration disables capture until explicitly configured/enabled. Preserve no-overwrite generation/add safety and existing Sentry support. Add a CLI telemetry configuration command only if needed to complete the connection workflow; dashboard configuration plus .env is a complete path.

## Validation and release gates

Independent LLM-as-judge review must cover privacy, correctness, OTel fidelity, API ergonomics, abuse/isolation, bounded resource use, retry/deduplication, retention, and operational truthfulness; resolve high/medium issues and record decisions. Unit tests exercise SDK failure cases; integration tests use real Workers/Durable Object SQLite runtime for persistence, scopes, quotas, rotation and retention. Browser acceptance sends from a scaffolded game through the real ingestion handler, then verifies dashboard display using the authenticated control route (test identity injected only in test harness). Run `pnpm verify`, relevant existing Playwright checks, standalone scaffold installation/build/tests, and package installation smoke. Attempt a live cloud round trip if existing credentials/configuration allow it; distinguish runtime/local proof from deployed proof.

## Owner follow-up

The initial limits and seven-day retention are engineering defaults to review alongside pricing. Registry publication, a production domain, symbolication, alerting and enterprise retention can follow without changing the transport contract. No owner input is required to implement or validate this design locally.
