### Optional creator attribution

Curated kit pages offer an unchecked opt-in. A download gets a random ID in `spawnkit-attribution.json`; ordinary downloads contain no attribution. Global Privacy Control and Do Not Track disable recording. The production Cloudflare D1 database stores kit ID, preparation time and the random ID. Source upload processing associates valid IDs with releases without passing source code or credentials to an analytics collector. Measurement failures cannot block downloads or builds. A private service binding handles ingestion with rate limits; the report requires administrator access. Anonymous report access returns 401.

A copied folder preserves its original download ID. Reports distinguish prepared downloads, downloads leading to at least one first production deployment, and first-deployed projects. Repeated releases count once per project; multiple projects can originate from one download without increasing converted-download count. Failed builds and existing projects whose first production deployment was already unattributed do not create new first-deployment conversions. These are opt-in download cohorts, not unique people or proof of SEO/AI referral. Local starts remain explicitly unobserved. Custom builder ZIPs are not attributed by this first implementation.

Analytics records and release links expire after 90 days, with bounded scheduled cleanup. Source archives follow normal hosting retention and may retain the attribution file. Removing the file opts future uploads out; existing analytics removal goes through support. The public privacy page describes this behavior. `pnpm seo:creators` saves an authenticated aggregate snapshot in ignored work/. Production persistence was verified with one synthetic opt-in download, then that exact test row was removed; the clean baseline is empty, not a fabricated conversion result. SQL regression tests cover copied folders, redeployments, failures, unknown/revoked IDs and expiration.
